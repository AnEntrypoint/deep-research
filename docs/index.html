deep-research

An agent skill that turns one research question into a cited, narrative report. A coordinator fans out parallel research subagents, collects their sourced notes, and has a report writer synthesise one report.

npx skills add AnEntrypoint/deep-research

1. Install

Run npx skills add AnEntrypoint/deep-research. The skills CLI reads skills/deep-research/SKILL.md from the repository and installs the skill folder.

The skill uses the agent skills format. Its frontmatter has name, which must equal the folder name deep-research, and description, which tells the agent when to load it.

2. Use

The skill loads for requests that need research across several sources: comparing options or alternatives, analysing trends or history, understanding markets or industries, or reviewing literature or studies. It ends in a narrative report.

Example request: Compare CRM platforms for small businesses across pricing, features, integrations and user reviews.

A single factual question needs one researcher and no decomposition.

Requirement. The coordinator must be able to spawn subagents with the Agent or Task tool. Without one, the agent researches the question directly.

3. Seven stages

StageWhat the coordinator does
1. ClarifyAsks follow-up questions with AskUserQuestion, only for missing or ambiguous details that would change the research: ambiguous terms, jurisdiction left unspecified, ambiguous entity names.
2. Title and foldersPicks a title and creates research_notes/<title>/ and reports/ in the working directory.
3. DecomposeSplits the question into mutually exclusive, collectively exhaustive subtopics. Sets the researcher count (section 4).
4. ResearchSpawns one foreground research subagent per subtopic, all in a single turn. Each subagent reads references/researcher.md first.
5. Extra roundOptional. Spawns researchers for a critical gap, once only. Then moves straight on.
6. ReportSpawns one report writer, which reads references/report-writer.md and writes reports/<title>.md.
7. DeliverSends the report with a file tool if one exists, else copies it to an outputs folder, else leaves it in reports/. Then gives a 3 to 5 sentence summary.

The coordinator never conducts research or writes the report itself. This keeps its context clean.

4. Researcher count

ResearchersUse whenExample
1No meaningful decomposition: a single factual question.Who won a given match?
3A few natural angles on a focused topic. Default when in doubt.Mechanisms, observed data, projections.
4Distinct facets or evaluation criteria.Pricing, features, integrations, reviews.
5Multiple independent entities, regions or domains.US, EU, China, UK, industry self-regulation.
6+A large enumerable set that needs systematic coverage.Adoption rates by state, assigned to regional clusters.

Subtopics that carry constraints from the question, such as time or place, pass those constraints to every subagent.

5. Titles and folders

The title names the folder and the report file, and appears as the report's title. It must be:

  • 3 to 6 words and under 50 characters;
  • sentence case, using letters, numbers and single spaces only;
  • free of hyphens, underscores, apostrophes and other punctuation;
  • written in the user's language, with accented and non-Latin letters kept as written.

Returning to an earlier topic. The new title must say what this request adds or changes, or repeat the earlier title with the next number. The most recent earlier report and notes folder are passed to the report writer as background. If that material is gone, the writer researches what is missing.

Independent redo. When the user asks for earlier research to be redone, the title is chosen the same way, but earlier material is not passed on.

An earlier request's folder is never renamed, moved or written into.

6. Research notes

Each researcher saves research_notes/<title>/<topic>.md. For each key question the note holds four parts:

  • Takeaway: one or two sentences.
  • Cited Findings: facts, statistics, claims or opinions, each with an inline source link. Conflicting sources are named as contradicted.
  • Inferences: conclusions drawn from the cited findings.
  • Gaps: questions that could not be answered, and why.

Researchers prefer primary sources, separate confirmed fact from speculation, and never invent a statistic. A claim without a source moves to Gaps. A typical run uses about 10 tool calls and stops at 15.

7. Report format

  • Title: about six words, active verb, sentence case.
  • BLUF: one paragraph of 5 to 8 sentences. It answers the main question first, so a reader can stop there.
  • Body: 3 to 5 signpost sections with narrative headers. Dense prose, bold key facts, no bullet lists, citations as ([Source](URL)).
  • Conclusion: one or two paragraphs of new takeaways, not a summary.

A claim with no source URL is dropped. The writer states uncertainty plainly and does not hedge with words such as "may" or "possibly".

8. Output files

research_notes/<title>/<topic>.md     one notes file per subtopic
reports/<title>.md                    the final report

Both folders sit in the directory used for earlier research in the conversation, or in the current working directory for a first request.

9. Limits

  • The skill needs a host that can spawn subagents. Without it, it falls back to direct research.
  • Findings are only as good as the sources the subagents can reach. Gaps are reported, not filled.
  • The extra research round is capped at one, to avoid timeouts and rate limits.
  • Earlier research is reused only while its report and notes folder remain on disk.
